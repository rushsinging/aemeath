# 3.16 设计图制作（archify · diagrams）

任何**新增、修改、重建设计图**的工作 MUST 遵循本分片。详细操作手册见
`tools/diagram/README.md`（构建命令、schema 对齐、实测方法），本文件只立硬规则。

## 1. 制品安置（DDD 层级，与编号文档同居）

1. 图跟随它描述的架构层级：`01-system/diagrams/<视图>/`（跨模块系统图）、
   `02-modules/<模块>/diagrams/<视图>/`（模块图）、`03-engineering/diagrams/<视图>/`
   （工程规则图）。**NEVER** 在 `04-architecture/` 新放图目录（仅保留其原有文档）。
2. 源与产物同目录：视图目录内 MUST 同时有 spec / data / inject 源文件与产物 `index.html`。

## 2. 命名

1. 视图目录用 kebab-case 语义名（如 `published-language-map`），**NEVER** 用编号
   （编号是 `NN-*.md` 文档的约定，不是图的约定）。
2. 布局源 `spec.<archify图类型>.json`；详情数据 `<视图短名>-data.json`；
   面板 `inject-<视图短名>.js`；产物固定 `index.html`；
   Mermaid 变体 `<视图>.mmd` / `<视图>-mermaid.svg`（可选，PR 内嵌用）。

## 3. 构建与验证

1. 统一构建入口：`python3 tools/diagram/build_diagram.py <视图目录>`。
   **NEVER** 手搓 archify 命令行拼产物（label 合入与面板注入由脚本负责）。
2. spec label 是节点显示名唯一真相源；构建期由脚本合入 data payload。
3. 产物 MUST 实测：`open index.html` 后用 agent-browser 做 DOM 断言
   （节点数 / 面板可点 / 缺陷标记），**NEVER** 仅凭构建成功就宣称图已完成。

## 4. 维护纪律

1. 代码变更后先更新 `*-data.json` 事实字段再重建，**NEVER 只改 index.html**。
2. 缺陷修复在 defect 文本标【已修复（阶段）】保留审计线索，**NEVER** 删除缺陷条目。
3. 符号退役 / 语义变更以代码为真相源清理 data；PL 面符号对账应零差异。
4. 变体（Mermaid / C4）非必需不新增；C4 已验证不适合链路叙事，**NEVER** 复用该形式画流程图。

## 5. 图型选择

- 系统/BC 分层 → `architecture`；泳道流程 / 数据链路 → `workflow`；
  调用时序 → `sequence`；数据管道 → `dataflow`；状态机 → `lifecycle`；
  时间轴 → `timeline`。
- showcase 校验对交叉 / 贴边零容忍：跨泳道边走外侧通道 via；phases 的 col 区间不可重叠。
