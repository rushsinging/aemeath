# 3.11 权限 / Hook / 审计

**Scope**：`agent/features/{policy,hook,audit}/**`——权限评估、hook 执行、审计记录。
**主触发**：改 `agent/features/{policy,hook,audit}/**`。
**次触发**：改 hook 执行环境变量注入。

## 3.11.1 Policy（权限）

- `PolicyPort`、`PolicyRequest/Decision/Mode` 位于 `agent/features/policy/src/domain.rs`；`ConfiguredPolicy` 位于 `adapters.rs`。
- Config committed permission mode 是唯一模式真相；CLI yolo 只作为 Config override。
- `AllowAll` **MUST** 放行所有授权性限制：项目外路径、read-before-write、Bash safety、Tool fuse；**NEVER** 增加敏感路径 hard deny。permission hook（PermissionRequest / PermissionDenied）的触发由授权决策流自然产生（AllowAll 下无决策 → 无事件），授权上下文不含 hook 开关维度；事件 hook（PreToolUse / PostToolUse / Stop 等）不受 AllowAll 影响，无条件执行。
- `AuthorizationContext` 唯一定义在 Tools Published Language；Policy 构造、Runtime 逐调用传递、Tool/Project/Hook 只读消费。
- **NEVER** 在 Runtime/Project/Tool/Hook 直接读取业务 `allow_all`，或恢复重复 PermissionMode/PolicyDecision。
- Deny/RequireApproval 仍为 Future PL；v0.1.0 Ask/AutoRead 映射 Standard 约束，不伪造审批。

## 3.11.2 Hook

- Hook 稳定 PL 与能力矩阵：`agent/features/hook/src/domain/**`；`HookPort`：`agent/features/hook/src/ports.rs`。
- Hook 进程执行 adapter：`agent/features/hook/src/adapters/process.rs`；环境白名单与 invocation 环境构造由 `agent/features/hook/src/adapters/**` 统一拥有。
- Hook Published Language / Config surface 与生产可达性 **MUST** 分开声明：PL 当前定义 26 个 HookPoint，实际 emit、directive/context/input consumer 与 message consumer 以 `docs/design/02-modules/hook/README.md §3.1` 的状态矩阵为准；未接线 point **MUST** 标为 Future，**NEVER** 以 enum 或 Config 可解析冒充生产支持。
- Main 使用 Full Hook capability；Sub 使用 `BoundaryHookPort` 的 BoundaryOnly capability。过滤 **MUST** 只依据 Hook-owned `HookPointMetadata.class`，并 **MUST** 转发 Stop 与 SubRun 生命周期 boundary；**NEVER** 复制 HookPoint allow-list 或恢复 EmptyHookPort。
- `hooks.max_attempts` 与 `hooks.max_stop_hook_blocks` 的默认值与 committed 配置由 `ConfigSnapshot` 唯一产生；Dispatcher 捕获 `HookExecutionPolicy`，每个 Main/Sub Run 冻结 `StopHookPolicy`，运行期 **NEVER** 读取 live config。这两个限制不属于用户 `HookSubscription`。
- `failure_policy` 当前是 Hook-owned PL/Dispatcher 契约，用户 `HookEntry` 尚未发布配置字段；在 Config schema、merge、snapshot 与消费测试完整接线前 **NEVER** 宣称可配置。
- Windows/non-Unix 当前不支持 Hook command execution：启动前 typed Unsupported、单次 `ExecutionFailed`、不重试；Windows CI 只证明 unsupported contract，不表示功能支持。
- **Hook 执行环境 MUST** 清空父环境，仅注入固定基础白名单、当前 invocation 变量及 `AEMEATH_PROJECT_DIR` / `CLAUDE_PROJECT_DIR`；Runtime **NEVER** 拼装或扩展 Hook 环境。
- Claude Code hooks 配置 → Aemeath hooks 的结构转换在配置层 `agent/shared/src/config/hooks.rs`，见 `3.9-config-compat.md`。

## 3.11.3 Audit（审计）

- 审计域当前为骨架（`agent/features/audit/`）。
- 旧的 Agent 审计日志 `~/.agents/logs/agent.log` 已废弃（保留兼容枚举，当前无写入点）。
