# 3.3 TUI / CLI

**Scope**：`apps/cli/src/**`——CLI 二进制入口、TUI（ratatui）、旧版 REPL（rustyline）、工具调用的 TUI 展示。
**主触发**：改 `apps/cli/src/**`。
**次触发**：改输入 / 渲染 / 快捷键 / 选区复制，或新增工具显示注册。
**配套**：所有 Rust 通用规范见 `3.2-rust-coding.md`；Agent 循环与 tool 执行编排在 `3.4-runtime.md`。

## 3.3.1 配置作用域展示

TUI **NEVER** 读取 `ConfigReader`、watch 或配置文件。只消费 SDK `ConfigReloadedEvent`：

- 根模型的 `RuntimePresentation` 只保存由启动与 SDK 事件推送的模型、上下文窗口和 thinking 等运行展示数据；它不是 Config BC 的 reader、watch 或 provider；
- 可见回显由 runtime 以 `SystemMessage` 生成（`share::i18n::runtime::config_reload`，按 `config.language` 选 zh/en），只说「已重载 + 生效边界（`立即生效` / `下次 Run 生效` / `重启 Session 后生效`）+ 组件文件数」，**NEVER** 做字段级 diff；
- `ConfigReloadedEvent` 只用于更新 config view、markdown spacing 与缓存失效，**NEVER** 生成第二条可见文本；
- 模型清单 **NEVER** 由配置事件主动推送：`/model` 对话框与 `/model <arg>` 补全在**显示时**请求 `ListModels`（runtime 先 `refresh_if_sources_changed` 再读 committed 快照）；`/model` 对话框 **MUST** 等新鲜列表到达后才渲染，**NEVER** 用旧缓存先行呈现；
- 展示逻辑不得重建 TUI、logger、MCP 或存储基础设施。

### 3.3.1.1 Connect 向导展示边界

- `aemeath connect` 与首次聊天初始化向导的 Catalog、stage、draft 校验、覆盖判断、Probe 和持久化全部属于 Config BC；TUI 只消费 SDK 通用 `ConfigFormView`，按服务端发布的 field/action schema 发送带 session id / revision 的类型化提交。
- `connect` **MUST** 复用通用 Config Form Ratatui renderer，**NEVER** 维护 Connect 专属 stage parser、手写行渲染或业务 action 映射；后续配置工作流也复用同一 renderer。
- Connect TUI **NEVER** 读取或写入 config/env/fs，**NEVER** 发起 Provider HTTP 请求，**NEVER** 自行拼接 Provider source、base URL、模型默认值或 User-Agent。
- API Key 输入必须遮罩；committed key 明文不得进入 SDK 只读 DTO、TUI model、review、错误或日志。
- TUI reducer 只维护输入框、焦点、页面投影和提交中状态；非法 stage、stale revision、Probe/Persist/Rollback 结果完全按 SDK DTO 展示，不以字符串匹配推导业务状态。
- 完整 Target 设计见 `docs/design/02-modules/config/02-provider-catalog-and-connect.md`。

## 3.3.2 TEA 副作用纪律

- **NEVER** 在 `update()` 中直接调用 `tokio::spawn`、hook notification、clipboard/image 等副作用——所有副作用通过 `Cmd` 描述并由 runtime 执行。
- TUI 状态遵循单一真相：用户输入的真相只在 model 的输入文档，**NEVER** 直接改渲染层缓冲。

## 3.3.3 工具调用的 TUI 显示（ToolDisplayEntry）

- 工具在 TUI 输出区如何显示，通过 `inventory` 收集的 `ToolDisplayEntry` 注册：
  - 收集点：`apps/cli/src/tui/render/output/tool_display.rs`（`inventory::collect!(ToolDisplayEntry)`）。
  - 内置工具显示：`apps/cli/src/tui/render/output/tool_display/tool_impls.rs`。
  - 任务类工具显示：`apps/cli/src/tui/render/output/tool_display/task_impls.rs`。
- 新增工具的展示样式：在对应 `*_impls.rs` 用 `inventory::submit!(ToolDisplayEntry { ... })` 声明，无需改渲染主循环。
- 注意：这套 `inventory` 仅控制**显示**。slash 命令由 Tools-owned `CommandDescriptor` / `CommandCatalogPort` / `CommandRouterPort` 注册和解析，经 SDK/Composition 注入；CLI/TUI/no-TUI **NEVER** 维护静态命令清单或独立业务 parser。
- 用户可见耗时（工具 header 后缀、BackgroundProcess Status deadline / Watch duration 等）**MUST** 统一走 `format_call_duration`：`<1s` 用百分秒小数（如 `0.85s`），其后为 `1.24s` / `1m 5s` / `1h 2m`；**NEVER** 向用户渲染 `ms`。内部字段名仍可保留 `_ms`。

## 3.3.4 ToolRenderPolicy 系统

`ToolRenderPolicy` 控制工具在 TUI 输出区的渲染行为，由 `ToolDisplay::render_policy()` 返回。

### 3.3.4.1 策略结构

```rust
pub struct ToolRenderPolicy {
    pub header: HeaderPolicy,   // header 行渲染策略
    pub details: DetailsPolicy, // details 区域渲染策略
    pub result: ResultPolicy,   // result 子块渲染策略
}
```

### 3.3.4.2 HeaderPolicy

| Variant | 说明 |
|---|---|
| `Standard` | 标准 header，带 ● marker |
| `Compact` | 紧凑 header，单行无 marker（如 TaskUpdate） |

### 3.3.4.3 DetailsPolicy

| Variant | 说明 |
|---|---|
| `Expanded` | 展开显示 details |
| `Hidden` | 隐藏 details |

### 3.3.4.4 ResultPolicy

| Variant | 说明 |
|---|---|
| `Hidden` | 不显示 result 子块（如 Read/Write/AskUserQuestion） |
| `Visible { max_lines, render_kind, tail_mode }` | 显示 result 子块 |

- `max_lines: Option<usize>` — 最大行数，`None` 表示全部显示
- `render_kind: ResultRender` — 渲染类型（`Plain` 或 `Diff`）
- `tail_mode: bool` — tail 模式，只显示最后 N 行（如 Bash）

### 3.3.4.5 ResultRender

| Variant | 说明 |
|---|---|
| `Plain` | 纯文本原样预览，保留原文（含行号/缩进），不做 markdown 重渲染。适用于 Read/Bash/Grep 等 |
| `Diff` | unified diff 渲染，解析 Edit 结果的 `---DIFF---` 为加减色 diff |

### 3.3.4.7 关键设计决策

- **渲染类型由工具显式声明**（`render_policy`），渲染层据此分发，不按 `---DIFF---` 字符或硬编码工具名猜测。
- **未注册工具回退策略**：`ResultPolicy::Visible { max_lines: Some(5), render_kind: Plain, tail_mode: false }`。
- **Agent 是使用 `DetailsPolicy::Expanded` 的内置工具**，展示 prompt 预览（截断 200 字符）。Bash 同样使用 `Expanded`，但展示命令全文（不截断，由渲染层 Word wrap 自动换行）。
- **Edit 是唯一使用 `ResultRender::Diff` 的工具**，显示全部 diff 行（`max_lines: None`）。
- **Bash header 显示 `goal` 参数**（命令目标/意图简述，必填）；命令全文在 details 区域不截断展示。空 `goal`（历史 session 反序列化）fallback 到截断的 command。
- **BackgroundProcessWatch header（#1964）**：Runtime 在展示前把账本 `invocation_goal` 注入 arguments.`goal`；TUI **只渲染** — 有 goal → **`Watch · {goal}`**，无 goal → 完整 `task_id`。**NEVER** 叠短尾 id，**NEVER** 等 typed result，**NEVER** 在 TUI 查账本。
- **Bash 使用 `tail_mode: true`**，只显示最后 5 行输出，避免长命令输出淹没 TUI。
- **TaskCreate 使用 `Compact` 单行模式**，description 合并进 header（`TaskCreate {subject}: {description}`）。
- Spinner 下方的 Task 状态列表 **MUST** 使用批次内稳定序号显示为 `<状态图标> #<seq_id> <Summary>`；`blocked by` 引用 **MUST** 使用同一批次内序号，**NEVER** 用当前列表枚举位置重新编号。
- **TaskBlockBy 使用 `Compact` 单行模式**，显示目标 `#id` 及完整替换后的依赖输入摘要；空列表明确显示清空依赖。
- **ToolResult 子块首行使用 `⎿` 圆角连接**作为 gutter marker（由 `gutter.rs` 按 `OutputBlockKind::ToolResult` 注入），连接到父 ToolCall header。
- **Tool display name 着色为 `ACCENT_BRIGHT`（Mauve）**，与参数文本（`TEXT`）和元信息（`TEXT_MUTED`）形成视觉层次。`format_header_line` 默认实现按 `display_name` 前缀拆分；不支持前缀匹配的自动 fallback 为整体 raw。
- `EnterWorktreeDisplay` 的 result-aware header override **MUST** 在结构化 result 缺失、解析失败或标记为 error 时回退消费原始 input；**NEVER** 使用伪默认值掩盖实际调用参数。
- **TUI 展示载荷上限为 64KB**（`TOOL_RESULT_PREVIEW_LIMIT`）：来源 #1444 的有界预览（防 GB 级结果物化成 document 时打出内存峰值），#1957 由 16KB 提升到 64KB；仍是**有界**兜底，常见大结果（如 95 条 ToolSearch ≈24KB）不再触发裁剪。
- **结构化 tool_result 超限时 MUST 保结构收敛**：`ToolSearch` 逐条截 `description`（≤256 字符）并按 64KB 预算二分收敛到最大可容纳前缀（至少 1 条），结果对象附 `tools_truncated: "total/omitted"` 标记；其他工具按字段逐层截断长字符串。**NEVER** 把整个 JSON 降级为截断字符串——那会使 `format_result_lines` 解析失败并退化成原始文本列表（两种 ToolSearch 卡片显示不一致即由此产生）。
- **省略标记文本 MUST 幂等**：已含 `chars omitted from TUI preview)` 后缀的字符串 **NEVER** 被二次截断，避免嵌套收敛时叠加多个标记。

## 3.3.6 Agent tool call 显示

### 3.3.6.1 AgentProgressEvent 数据流

Sub-agent 的实时活动通过 `AgentProgressEvent` 从 runtime 流向 TUI，**MUST** 保持结构化传递，**NEVER** 中途压扁成字符串：

```
SubAgentRun.role_name_for_log / model_name_for_log
  → AgentProgressKind::Started { role, model }   (share 层)
  → setup.rs emit Started 事件                    (runtime 层)
  → AgentProgressKindView::Started                (SDK 层透传)
  → UpdateAgentMeta intent                        (TUI adapter)
  → ToolCall.agent_meta                           (TUI model 层)
  → AgentMetaView                                 (view_model 层投影)
  → merge_agent_meta 合并到 JSON 副本             (render 层)
  → AgentDisplay::format_header_line_with_result 显示
```

关键约定：

- **MUST** `AgentProgressEvent` 新增字段 **MUST** 加 `#[serde(default)]`，保证历史 session 反序列化兼容。
- **MUST** view_model 层 **MUST NOT** 直接引用 model 层类型（架构守卫拦截），**MUST** 定义独立的 view 类型（如 `AgentMetaView`）并在 view_assembler 处投影。
- **MUST** Agent tool 的 role/model 显示（`[role: xxx] [model: xxx]`）**MUST** 在 `AgentDisplay::format_header_line_with_result` 中处理——这是实际被调用的入口。**NEVER** 只改 trait 默认方法 `format_header` 而不动覆写方法，覆写会切断调用链。
- **MUST** main agent 的 ToolCall（Read/Write/Bash 等）`agent_meta` 始终为 `None` → 天然不显示 role/model。**NEVER** 在主 run step context 注入 role/model。

### 3.3.6.2 Sub-agent 实时活动展示（未来）

`AgentProgressEvent` 是 sub-agent → TUI 的结构化实时事件通道，为后续"实时显示 subagent 在做什么"打下基础：

- 当前：`Started` 携带 role/model；`Message` / `ToolCalls` 通过 `AgentActivityLine { kind, content }` 结构化传递，marker 与缩进由 renderer 统一注入。
- `ToolCalls` 正文只包含工具 display name 和参数摘要，NEVER 包含 `→ `；普通 Message 不得因文本内容被推断为 ToolCall。

## 3.3.7 Runtime 权威终态消费

- TUI **MUST** 只消费 Runtime 经 SDK 发布的权威业务终态，**NEVER** 持有或复制 Runtime 状态机。
- TUI **NEVER** 缓存或关联 `run_id`、`step_id` 来决定成功、取消、失败、终止或超时；Run/RunStep 生命周期事件只用于观测或辅助展示，不得改变 terminal cause。
- 实时事件与 Resume 历史 **MUST** 进入同一 ConversationModel terminal 入口，并对同一持久化事实渲染等价终态与耗时。
- 每个 run step **MUST** 最多渲染一个 terminal notice；收到取消终态时必须结束 processing，且不得同时出现任何正常完成展示。
- Runtime/SDK 终态链路 **MUST** 分别覆盖 SDK→TUI adapter、TUI event→intent、model/reducer→render 及最终场景测试；场景测试 **NEVER** 替代相邻层契约。
- 取消场景测试 **MUST** 证明无需预先收到 Run/Step identity 事件即可正确渲染，并断言整个成功展示类别均不存在。

### 3.3.7.1 Reflection activity 展示规范

- TUI **MUST** 只消费 Runtime 经 SDK 发布的 typed activity/event（`RunPurposeView`、`ActivityDetailView::Reflection { trigger }`、`ActivityStateView`、`ChatEvent::CommandResultText { text, is_error }`）：**NEVER** 读取 reflection/memory 配置、**NEVER** 复制 Runtime 的 Run 状态机，也 **NEVER** 从文案字符串推断 trigger、status 或终态。
- **映射**：root `RunPurposeView::Reflection` → `TuiRunPurpose::Reflection`；leaf `ActivityDetailView::Reflection { trigger }` → `TuiActivityDetail::Reflection { trigger }`，trigger 恰为 `Interval` / `PreCompact` / `Manual` 三种；`event_mapping` 按变体逐个转换，**MUST NOT** 做字符串匹配。
- **Running**：purpose=Reflection 的 root 与 Running 的 Reflection leaf 参与既有 live root spinner（与 `purpose=Main` 同一路径，`activity_summary` 不区分二者）；phase label 为 `Reflecting…`，由 detail 分发得到。
- **terminal**：`ActivityStateView` 的终态为 `Succeeded` / `Failed` / `Cancelled` / `Terminated`；leaf 终态先收口 phase 文案（`Reflecting…` 消失），root 仍 Running 时外层 spinner 保留，root 终态才停止 spinner——root 与 leaf 的终态生命周期分层，**MUST NOT** 合并为单一终态判断；终态展示来自结构化 state，不做文案反推。
- **`/reflect-now` CommandResultText 文案契约**：文案与 `is_error` 由 Runtime 的唯一策略成对产出，TUI 只按 `is_error` 分流（error → Error 块，非 error → System 块），**NEVER** 复制文案映射。当前六态与 Runtime 精确一致：
  - Succeeded 有变更：`Reflection 已完成：更新 {changed} 条记忆；摘要可用 /reflect 查询。`（非 error）
  - Succeeded 无变更：`Reflection 已完成：没有记忆变更。`（非 error）
  - Failed：`Reflection 执行失败；详情见日志。`（error）
  - Cancelled：`Reflection 已取消。`（非 error）
  - TimedOut：`Reflection 超时，已中止。`（非 error）
  - DisabledSkipped：`Memory 或 Reflection 未启用；请在配置中开启后重试。`（非 error）

  另有 input gate 的 busy 跳过回执 `Reflection 已在运行或等待运行结束，已跳过本次手动触发；稍后再试。`（非 error），同样走 `CommandResultText` 通道。
- **`/reflect` 历史输出规范**：卡片式——标题行（本地时间 `YYYY-MM-DD HH:MM` + trigger + 状态符号 `✓/✗/…` + apply 状态 + 耗时秒化 + tokens `in→out tok` + 非零 outdated 计数），Deviations / Suggestions 组的内容全展开（每条单行化、按字符截断 100 + `…`）。内容来自 Memory 的显式内容投影（`list_with_content`），Safe 边界不变：默认摘要（`list`）NEVER 携带内容；LLM 原文、prompt 与 reflection record id 正文 NEVER 出现在输出中。
- **队列与 processing**：purpose=Reflection 的 root **NEVER** 向普通会话队列（`queued_submissions`）写入占位；`ActivityChanged` **NEVER** 直接置 `is_processing=true`——processing 仍由提交路径进入，由 `Done` / `Cancelled` 等 Run terminal 事件收口为 false；Reflection spinner 由 typed activity mirror 独立驱动，与 processing 解耦。
- **相邻层契约**：SDK typed view（序列化/字段）→ TUI adapter（逐变体映射）→ model/reducer → render 各层 **MUST** 各自保有契约说明；场景测试（`app/scenario_tests/chat.rs`：spinner 出现/消失、三态 notice 样式、队列洁净）覆盖 runtime event → model/reducer → render 全链路，**NEVER** 替代相邻层契约。
- **Esc / Ctrl-C 取消入口**：统一发无 identity 的 `CancelCurrentRun`（TUI 唯一取消入口；门控为 `is_processing || has_live_main_root`——turn 进行中或 activity mirror 存在 live Main/Reflection root，后者与 spinner 同源）。Runtime 控制面裁决当前执行单元：有 active step 走 CancelStep 协议，Manual Reflection 按 `RunIntent` 取消执行体，Conversation 的 step 间隙返回 `NoActiveStep`。TUI **NEVER** 持有 run/step identity 取消面（可寻址 `RunControlClient` 仅供 Server/Coordinator 管理端），只映射 `CancelCurrentRunOutcome`，**NEVER** 自行推断 Run 生命周期。

## 3.3.8 Markdown 间距策略

- Markdown 空白处理 **MUST** 由 `ui.markdown_spacing` 选择全局 `normal` / `compact` 模式，并允许 `ui.markdown_spacing_overrides` 对 `paragraph`、`heading`、`list`、`quote`、`table`、`code` 做单元素级覆盖。
- `normal` **MUST** 保持既有渲染行为；`compact` **MUST** 仅消除块级 Markdown 之间的外部空行，**NEVER** 删除 fenced code block 内部空行。
- 配置快照中的间距策略 **MUST** 经过 runtime → SDK → TUI adapter → model → renderer 全链路传播；reload 后 **MUST** 使现有输出立即重渲染。
- `OutputBlockCacheKey` 与 gutter 缓存键 **MUST** 包含间距策略指纹，**NEVER** 通过清空整个 cache 隐式保证正确性。

## 3.3.9 显示文本控制字符策略

- 所有进入输出区渲染的文本 **MUST** 经 `view_model::display_text::normalize_display_control_chars` 归一化（单一真相）：`\t` → 4 空格、`\n` 保留、其余控制字符（C0/C1/DEL，含 ESC/C1-CSI）→ `U+FFFD`。
- 渲染防线 **MUST** 覆盖 `render_self` 分发入口、`wrap_spans_with_prefix` 入口、`RenderedLine` 构造（`new`/`with_plain`/`with_plain_and_links`）三层；新增消息块 **NEVER** 绕过 `render_self` 分发自行渲染原始文本。
- 零宽格式字符（ZWSP/ZWJ/组合符，非 Cc 类）**保留**。
- tool result display 文本 **MUST** 复用同一函数，**NEVER** 再实现局部 tab 展开。
