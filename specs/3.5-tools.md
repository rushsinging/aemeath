# 3.5 工具（Tool）系统

**Scope**：`agent/features/tools/**`——Tool Published Language、Catalog/Execution 端口、内置与 MCP adapter。
**主触发**：改 `agent/features/tools/**`。
**次触发**：新增内置 Tool，或改 MCP 工具加载 / 注册。
**配套**：tool 在 Agent 循环中的执行编排在 `3.4-runtime.md`；工具调用的 TUI 展示在 `3.3-tui-cli.md`。

## 3.5.0 内置工具输入契约（`goal`）

- 每个内置工具 `*Input`（含 Skill 手写 schema）**MUST** 含必填字段 `goal: String`：短意图（约 3–5 词），供 TUI Header 与后台账本 summary 使用。
- schema `required` **MUST** 含 `goal`（字段级 `#[serde(default)]` 会从 required 剔除，**NEVER** 仅靠字段级 default 冒充必填；兼容旧 transcript 用 **struct 级** `#[serde(default)]`，空串由 adapter 拒绝或 Display fallback）。
- Agent：字段名 `goal`；`#[serde(alias = "description")]` 兼容旧 transcript；schema **NEVER** 再暴露 `description` property。
- 转后台时 runtime `invocation_summary_text` **MUST** 产出 `{友好名} · {goal}`（友好名 = `sdk::tool_display_name`）；缺 goal → `{友好名} · (no goal)`，**NEVER** 回退 `tool=… input=…`。
- MCP 动态工具：本契约非硬门禁；无 `goal` 时 TUI 可 fallback 工具名 + 截断参数（见 `docs/design/02-modules/tui/06-tool-goal-and-background-summary.md` §6）。
- L0 锁死：`agent/features/tools/src/domain/types/goal_contract_tests.rs`。

## 3.5.1 Catalog / Execution 与 Scope/Profile

- `ToolCatalogPort` / `ToolExecutionPort`：`agent/features/tools/src/domain/ports.rs`；Descriptor、Invocation、Outcome 等 Published Language：`agent/features/tools/src/domain/published_language.rs`。
- 生产 Runtime 使用 Catalog / Execution 双端口，不取得 `ToolRegistry` 或 `Tool` 实例。两端由 `agent/features/tools/src/adapters/composition.rs` 的窄 factory 基于同一个私有 `ToolBacking` 装配；具体 backing、registry 与 adapter 不从 crate root 暴露。
- Catalog 按 Scope/Profile 投影 schema；Execution 在调用时复验 Tool 存在性、Scope/Profile 授权并执行。schema 校验实现唯一归 Tools：`agent/features/tools/src/domain/schema_validator.rs`；Runtime 的 `application/agent/input_validation.rs` 仅保留兼容 re-export / phase peel，不得复制规则。
- Tool 自身 **MUST** 通过 Catalog 发布准确的 `ConcurrencyDeclaration`；Bash 等 workspace-changing Tool **MUST** 声明 sequential-only。Runtime ordinary/streaming 编排按该声明分类，并按原始 ToolCall 提交顺序执行 sequential-only 调用；ToolCall ID 只承载 identity，不承载 ordering。
- `RegistryScope` / `ToolProfile` 与“只收缩”规则：`agent/features/tools/src/domain/scope_profile.rs`。Main 是 `all()` baseline；Sub 必须由 Main 经 `derive_restricted` 构造。内置工具名称、required capabilities、Scope 成员关系与 factory 的单一规格在 `agent/features/tools/src/adapters/registry.rs`。
- `ToolRegistry` 是 Tools adapter 内部 backing；唯一稳定 `Skill` Tool 同时注册到 Main/Sub Catalog，并在调用时经 `SkillLoadPort` 按 identity 加载正文。
- Skill Published Language 与端口位于 `agent/features/tools/src/domain/{skill_pl,skill_ports,skill_state}.rs`；`SkillCatalogPort` 仅返回 metadata，`SkillLoadPort` 调用时读取单个正文。`SkillLoadStatePort` 只发布 `(Main Session, Agent scope, canonical skill, content revision)` 的原子 compare-and-record 契约，Tools 不持久化状态。Context/TUI 禁止持有正文。

## 3.5.2 ExecutionScope、资源与 suspension

- `ExecutionScope` 是固定八字段纯值对象：run/parent id、workspace id/root 快照、invocation source、registry scope、profile、deadline；**NEVER** 放入 registry/store/channel/token/semaphore 或 Project wiring。
- `ToolExecutionContext` 只含私有 `scope + ports`。文件工具只经 `WorkspaceRead` 解析路径；`WorkspaceControl` 仅允许 Bash、EnterWorktree、ExitWorktree 使用，accessor 保持 crate-private。
- `WorkspaceViews` 必须在 Runtime adapter 转换；Runtime 自持 `WorkspacePersist`、并发 semaphore、timeout、Policy/Hook 与等待机制，Tools domain 禁止 Tokio channel/token/semaphore。Memory 能力直接使用正式 `MemoryPort`，不得恢复 legacy compatibility bridge。
- AskUser adapter 只解析并返回纯值 `ToolSuspension::UserInteraction`：`agent/features/tools/src/domain/suspension.rs`、`agent/features/tools/src/adapters/ask_user.rs`。request id、waiter、continuation、await/resume 与取消归 Runtime；当前 typed suspension 边界不代表完整 Interaction 状态机已经收口，兼容路径不得成为第二状态真相。
- Command Published Language 与端口位于 `agent/features/tools/src/domain/{command_pl,command_ports}.rs`；唯一生产 adapter 位于 `adapters/command.rs`，由 `tools::composition::wire_commands` 装配。SDK 只 re-export，CLI/TUI/no-TUI **NEVER** 定义第二份 Descriptor、Catalog 或 parser。
- Skill 使用 metadata Catalog + call-time Load，并通过唯一稳定动态 Skill Tool 执行；Command Router 只发布 typed `SkillRequest`。

- `TaskUpdate` 只发布普通单字段更新（status / subject / description / priority）；任务依赖由独立 `TaskBlockBy { id, block_by_ids }` 发布，`block_by_ids` 表示完整替换后的集合，空列表清空依赖。
- `TaskBlockBy` adapter **MUST** 委托 Task-owned 原子集合替换命令；**NEVER** 在 Tool 层逐条 add/remove 形成部分成功。目标、重复 ID、当前 Batch 成员关系与 DAG 无环性必须在提交前验证，失败不得改变 Task revision 或任一依赖边。

## 3.5.3 MCP 工具

- MCP 主体在 `agent/features/tools/src/adapters/`：`mcp_manager.rs`、`mcp_tool.rs`、`mcp.rs`、`read_mcp_resource.rs`、`list_mcp_resources.rs`。
- MCP 加载器：`agent/features/runtime/src/application/startup/mcp_loader.rs`；MCP 外部协议 adapter：`agent/shared/src/adapter/mcp.rs`。
- dynamic-source seam 保持保守：动态 callable 可进入私有 backing，但不会因此自动获得 Scope 成员资格或 Profile 授权，也不改变既有连接生命周期。
- MCP server 配置来源：`~/.agents/mcp.json`（动态加载，当前通过 `serde_json::Value` 配置——属开放决策）；description 来自 MCP server 透传。
- MCP Ready 的显式连接生命周期、disconnect 撤销/refresh、Catalog revision、稳定身份与版本协议均未完成，不得从 source seam 推导 Ready。

## ToolSearch（#1955）

- 生产 Main/Sub 执行上下文 **MUST** 注入当前 scope 的 tool catalog（`with_catalog`），否则非空 query 恒空。
- ToolSearch **MUST** 同时词法搜索 tools 与 skills；结果条目带 `kind: tool|skill`。
- 空 query **MUST** 只列 tools，**NEVER** 倾倒全部 skills。
- 无 systemone / scoring 不可用时 **MUST** 纯词法排序；低置信语义重排失败静默回退词法。
