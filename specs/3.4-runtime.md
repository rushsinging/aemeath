# 3.4 Runtime 引擎

**Scope**：`agent/features/runtime/**`——Agent 主循环、tool 执行编排、token budget、对话压缩（compact）、成本追踪、slash 命令系统。
**主触发**：改 `agent/features/runtime/**`。
**次触发**：改暂停 / 恢复 / 重试 / 取消 / 超时 / terminate / 终态投影；改成本追踪；新增 slash 命令。
**配套**：Tool Published Language、Catalog/Execution 端口与 MCP 主体在 `specs/3.5-3.5-tools.md §3.5`；provider 调用在 `specs/3.6-3.6-provider.md §3.6`。

## 3.4.1 配置应用边界

- Runtime **MUST** 在接纳真实用户输入、创建 Main Run 前调用 `ConfigReader::refresh_if_sources_changed()`；同一次 Run 内 **NEVER** 再 refresh。
- Main Run 与每个新 Subagent Run **MUST** 捕获一个 `RunConfigSnapshot`；provider binding、WebSearch 的 HTTP `User-Agent`、`allow_all`、hooks、language、timeout 与 context size 随该 Run 固定。
- `api.user_agent` 属于 `Run` scope：Provider 与 WebSearch 在下一 Run 使用冻结快照；当前 Run 不变。
- Run Step 只从所属 `RunConfigSnapshot` 构造 `ContextRequest.config_snapshot`，**NEVER** 读取 `ConfigReader` / `ConfigQuery` 或配置文件。
- `SessionRestartRequired` scope 仅标记 pending session revision；当前 TUI/logger/MCP/storage 基础设施保持不变，成功 session resume 后清除 pending 标记。

## 3.4.2 会话历史唯一真相

- **MUST** 会话历史唯一可变真相属于 Context Management 的 `CanonicalSession` backing。
- **MUST** Runtime 每个 Run 用显式 Step message ownership 记录当前 Run/RunStep 的消息投影；**NEVER** 通过消息位置、长度、历史数量或索引推断归属。历史通过 `ContextPort::build_window` 读取，finalized Step 通过 `append_and_persist` 提交。
- **NEVER** Runtime 生产代码引用 `context::session::*`、`ChatChain` / `ChatSegment`，或恢复 `current_chain` / `frozen_chats` / `active_summary` 第二 backing。
- **NEVER** 恢复 `save_chain`、loop-exit auto-save 或 Runtime 自写 Session 文件；持久化由 Context 复用 Storage AtomicBlob。
- **MUST** `ChatRequest` 只传增量 `user_input`，**NEVER** 传全量消息历史。
- **MUST** idle `/compact`、reset 与自动 compact 经 ContextPort；启动 resume 与运行期 `/resume` 经同一 `MainSessionWiring::resume_session` 协调器。

## 3.4.3 Tool 执行编排

- 执行流程：LLM 返回 tool_use → Runtime 取得本次 Scope/Profile 的 Catalog snapshot → Policy/Hook/并发/timeout 编排 → 经 `ToolExecutionPort` 执行 → 结果注入回消息。
- Main/Sub Runtime 只持 `Arc<dyn ToolCatalogPort>` / `Arc<dyn ToolExecutionPort>` 与 Published Language，不持 `ToolRegistry`、不取得或调用 `Tool` 实例。生产装配入口在 `application/client/from_args.rs`，Tools 私有 backing 与双 adapter factory 见 `specs/3.5-3.5-tools.md §3.5`。
- Catalog 提供 schema/并发/timeout 描述；Execution 复验存在性、Scope/Profile、schema 后调用 Tool。schema 所有权归 Tools，Runtime 的 `application/agent/input_validation.rs` 仅为兼容 re-export / phase peel。
- Runtime 自行持有 `WorkspacePersist`、并发 semaphore、timeout、Policy/Hook、取消实现与 interaction waiter；这些 **NEVER** 流入 Tools domain。`WorkspaceViews` 只在 Runtime adapter 转成窄 live capabilities，`ExecutionScope` 只传纯值快照。
- Tools 返回 typed `ToolSuspension`；Runtime 映射为交互值并拥有 request identity、等待、continuation、resume 与取消。旧 Runtime-owned AskUser oneshot 仅为兼容路径，不得据此复制第二套状态机。
- 唯一稳定 `Skill` Tool 经正式 Tool Catalog/Execution 发布并执行；Main/Sub Context 只注入 metadata directory，正文由 `SkillLoadPort` 在调用时按 identity 加载。Runtime 只接纳 typed `SkillRequest` 并投影模型意图，**NEVER** 读取 Skill 文件。
- Runtime **MUST** 为 Skill 去重装配稳定主体作用域：Main Session 的所有 Main Run 共用 `SkillLoadScope::Main`；每个 Sub-agent instance 创建一次独立 scope 并在其全部 Step/Tool round 中复用。Sub RuntimeContext 继承父级 Context-owned `SkillLoadStatePort` 与 Main Session identity，**NEVER** 使用 `run_id` 或 Sub 的 isolated Session 作为 durable 去重真相。

## 3.4.4 取消、超时与终态协议

- **MUST** 将取消视为包含请求受理、执行资源收敛、terminal receipt 持久化、Step finalize 和权威终态投影的协议，**NEVER** 简化为一次 token 操作。
- **NEVER** 通过 drop Tool future 假定外部副作用已停止。Runtime 收到取消后 **MUST** 等待 Tool cleanup 与 terminal receipt 持久化完成，再 finalize Step。
- 外层 timer 触发不自动构成硬超时。阻塞型 Tool **MUST** 在 blocking 边界执行并合作式检查取消；外部进程 Tool **MUST** 终止进程树、等待宽限、必要时强杀并回收。
- timeout、cancel、cleanup 与 terminal receipt **MUST** 由 Runtime 的统一监督入口编排；**NEVER** 在 Main/Sub、普通 Tool、Agent 或 approval continuation 中复制第二套机制。
- **MUST** 区分 Runtime 生命周期状态与业务终态。**Runtime 生命周期完成不等于业务成功**；内部 `Completed` 若包含取消、失败、终止、超时或其他非成功原因，出站事件 **MUST** 保留真实用户语义，**NEVER** 投影为成功。
- Runtime 是用户可见终态的唯一真相源。`RunStepCancelled` 等是生命周期观测事件；`Cancelled`、`DoneWithDuration`、失败/终止事件是权威业务终态。SDK/TUI **NEVER** 根据 identity 或事件顺序重新实现状态机。
- 一个 turn **MUST** 只发布一个用户可见终态；成功、取消、失败、终止、超时互斥，**NEVER** 同时发布冲突终态。
- 只有确认完成资源收敛的取消才能投影为已取消；`CancellationUnconfirmed` **MUST** 保持不确定语义，**NEVER** 伪装成取消成功或业务成功。
- 实时与 Resume **MUST** 对同一持久化事实投影等价业务语义，并保留终态原因、耗时及用户可见结果。

## 3.4.5 token budget / 压缩 / 成本

- token 估算由 Context BC 的 `context::api::compact::estimate_tokens` 提供，Runtime 在 `application/{agent,chat}` 编排中消费。
- Task 进度上下文由 `TaskUpdate(status)` 的 typed tool result 承载；Runtime **NEVER** 从 Task 快照构造独立 reminder，也 **NEVER** 在 `ContextWindow → InvocationRequest` 映射时装饰用户消息。canonical message、SDK/TUI 事件和持久化 JSON 不因进度摘要发生隐式变更。
- **SHOULD** 修改涉及暂停 / 恢复 / 重试逻辑时同步检查 Context token estimation 调用点。
- 成本追踪与定价：`agent/features/runtime/src/application/cost/pricing.rs`。
- **SHOULD** 成本追踪逻辑更新时同步更新 `pricing.rs`。
- 成本历史落盘在 `~/.agents/cost_history.json`。

## 3.4.6 slash 命令系统

- slash 命令的 SDK/TUI 入站路由属于 `application/client`；具体命令能力由对应 Feature 的 Published Language / Tool 提供。
- Command Published Language 与双端口由 Tools 独占，SDK 直接 re-export，Composition 向 TUI/no-TUI 注入同一 Catalog/Router；Runtime `PendingCommand` 仅作为目标 BC handler adapter，**NEVER** 再解析 slash 名称、alias 或参数 schema。
- Runtime 内不维护固定层命令注册表；新增命令必须先进入 Tools-owned Descriptor/Catalog，并由实际 owner 提供 handler，**NEVER** 恢复 SDK/TUI/Runtime 静态清单。
- 命令在 TUI 的展示样式见 `specs/3.3-3.3-tui-cli.md §3.3`。
