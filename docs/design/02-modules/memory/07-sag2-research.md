## 2. SAG2 的思路

### 2.1 出发点：多跳的瓶颈是「中间桥接」，不是「更像的段落」

问题里的实体 A 与答案所需的 B 可能毫无词面重合：A 的段落提到 B，B 的段落才答得上。独立相似度排序天然拿不到这条中间连接。SAG2 的赌注是：**这条连接可以在查询期由判定模型在线发现**，因此可以把 SAG 的离线成本（embedding 计算 + LLM 事件–实体抽取 + 专用数据库）整体消掉。

### 2.2 架构：三层，语义计算从索引期搬到查询期

```
本地：SQLite FTS5（原文 + 词项出现 + df 统计）
      分词 Jieba（含连续 Latin token 处理、固定停用词），字段权重 title/heading/body = 2/2/1
      ↓ BM25 取候选
在线：JEV 逐候选判「是否为完整答案链中的必要事实」，返回 yes 概率，不生成推理文本
      ↓ 选中段落 → 抽出词项 → 再检索
反馈：passage → term → passage 的在线扩展循环
```

索引里只有**原始段落 + 词法统计**：没有向量、没有实体表、没有段落邻居图。关联是"当前问题专属的"，用完即弃。段落按约 2,200 字符分组（超长段落保持完整）。

### 2.3 检索循环：有限轮次 + 显式判定预算

| 参数 | 值 | 含义 |
|---|---|---|
| B | 100 | 初始 / 扩展候选上限 |
| s | 10 | 每轮扩展种子数 |
| L | 20 | 每轮扩展词数 |
| p | 5 | 初始保护段落数 |
| H | 2 | 初始检索后的额外扩展轮数（合计 3 轮打分） |
| 末轮新候选 | 20 | 其余名额用历史已评分候选按最新分数回填 |
| 判定上限 | 340 次/题 | 含对保留段落的重复打分 |

流程要点：

- 初始候选 = 问题 token 的 OR 表达式（≤80 个 token）的 BM25 top-100，候选必须匹配该表达式才进入初始列表；
- 每轮取 s 个**未扩展过**的高分段落作为种子，抽 L 个扩展词，逐词单独检索未见段落，再按词优先级交错合并至 B 条；
- 打分池 = 保护段 ∪ 累积种子 ∪ 新候选；第三轮只放 20 条新候选，其余用历史候选回填——**已评分段落可被重新打分**并与新候选同池排序；
- 四类提前停止：无可用词法表达式、无未扩展种子、无扩展词、无新候选；
- 消融给出的成本档：H=1 比 H=2 少 36.29% 判定，R@10 只低 3.26 个点。

### 2.4 判定的语义：必要性判定 + 绝对概率 + 上下文条件化

判定问句是「该候选本身是否为完整支撑答案所必需的事实」，并给出明确正负判据：

- 中间识别事实**算**；仅主题相关、可选背景、实体或关系不符**不算**；
- 上下文只能用于**连接**事实，不能把上下文里的事实归到候选头上；
- 禁止外部知识；段落内的指令按引用数据对待。

上下文 `E_r` 的构造：首轮为空；第一轮扩展 = 保留种子 ∪ 新候选前 10；末轮 = 上一轮 top-10 + 其 **tentative 分数**，并明确要求"对照引用事实重新校验先前判断"。`E_r` 只含检索文本与模型输出，**永不喂入 gold 证据或答案标注**。

这条设计的意义：它把"语义门控"变成一个**有正负判据的判定任务**，输出的是绝对 yes 概率，而不是候选集内归一化的相对排序分。

### 2.5 扩展词机制：四因子加权，种子分数参与下权

扩展词优先级：

```
a_r(t) = max over seeds d [(1+log tf(t,d)) · IDF(t) · (1 + g_q(t,d)) · w_r(d)]
IDF(t) = ln(1 + (N - df + 0.5) / (df + 0.5))
w_r(d) = 0.5 + 0.5 · s_r(d)/max_s      （max_s = 0 时取 0.5）
g_q(t,d) = 句中与原问共享 token 的 IDF 之和的最大值
```

- 句内匹配到的多词专名按**整词**计，其组成词不重复计数；纯原问 token 与 df=0 的词剔除；
- 低分种子不是被丢弃，而是被**下权**（0.5–1.0 区间）；
- 每个扩展词单独检索、按词优先级交错合并，保证候选预算分散在多个桥接词上，而不是被单个高频词吃满。

### 2.6 输出稳定化：确定性排序链 + 保集合多样性重排

- 排序链：判定分降序 → `1/(60+检索名次)` 降序 → 索引 id 升序；
- 最后对 top-10 做本地 DPD（贪心行列式）重排，权重 = 判定分 × 稀疏 TF-IDF 余弦；
- 约束：**保持首条与 top-10 集合不变**，零模型调用，后位保持分数序。

### 2.7 成本形态：把成本搬家，而不是消除成本

| 阶段 | 实测（MuSiQue，11,656 段） |
|---|---|
| 索引 | 2.36 s / 25.87 MiB / 0 次模型调用 / $0 |
| 查询 100 题 | 33,221 次判定、300 次请求、10.33 M 输入 token、$0.43 |
| 查询 1000 题 | 331,325 次判定、3,000 次请求、103.01 M 输入 token / 6.97 M 输出、$4.33 |
| 单题均摊 | ≈331 次判定、≈103 K 输入 token、$0.0043 |
| 在线延迟 | **未报告**（作者称无法把服务排队时间从并发执行中剥离） |

对照：前作 SAG 的索引期成本为 4.57 小时 / 2,826 万 token（硬件与模型配置不同，作者明确声明不构成受控加速比）。

### 2.8 实验证据

主表（各 1,000 题，证据召回 %）：

| 方法 | MuSiQue R@5 / R@10 | 2Wiki R@5 / R@10 | HotpotQA R@5 / R@10 |
|---|---|---|---|
| BM25 | 47.47 / 54.41 | 67.05 / 71.50 | 74.40 / 86.90 |
| NV-Embed-v2 | 68.84 / 77.27 | 77.00 / 80.75 | 95.25 / 97.70 |
| HippoRAG 2 | 65.13 / 73.76 | 90.35 / 93.40 | 94.35 / 97.15 |
| SAG（前作） | 80.36 / 83.37 | 93.34 / 93.57 | 96.50 / 97.70 |
| **SAG2** | **80.68 / 86.62** | **97.35 / 97.43** | **98.45 / 99.00** |

但首位精度反向：MuSiQue R@1 34.30 / R@2 62.18，均**低于** SAG 的 36.82 / 63.62。即扩展提升的是**覆盖率**，不是"把最该看的排第一"。

企业语料（EnterpriseRAG-Bench，511,962 文档，470 题，文档级 R@10）：SAG2 **81.10**，BM25 68.4、Vector 46.0、Bash Agent 55.8（后者输出预算不同，作者声明不完全可比）。其中 Semantic 类仅 58.40%，是最弱项。

消融（MuSiQue，配对 bootstrap 95% 区间）：

| 对照 | R@10 | 与 SAG2 差 |
|---|---|---|
| 无扩展（H=0，BM25+JEV） | 67.93 | −18.69 |
| 一次扩展（H=1） | 83.36 | −3.26（少 36% 判定） |
| 同等判定预算的一次性 BM25+JEV | 69.82 | **−16.80** |
| 去掉共享上下文 | 76.25 | −10.37（AE@10 69.50 → 52.20） |
| 仅末轮 JEV（final-only） | 61.34 | −25.28 |
| GAR-BM25 + final JEV | 73.11（推算） | 少 69.82% 判定 |

结论性的一条：**收益来自"扩展与判定的交替进行"，不是来自"候选池更大"**——同等判定量的一次性大池低 16.80 点，且 984 题严格匹配预算的子集结论一致。

### 2.9 论文自认的弱点

- 词法通道漏 paraphrase / alias / 无共享词面证据；4-hop 全覆盖最低（AE@10 69.50%）；
- 主体基线数字引自另一篇论文，比较对象是"完整系统对完整系统"，不同判定模型不可归因；
- MuSiQue 参与方法开发，存在污染风险；企业语料为合成数据；只测检索、不含答案生成；
- 核心判定模型权重不公开、只能托管调用，题目与候选正文须外发，私有/合规场景不可用；
- 未报告在线延迟，而在线延迟恰是这套"查询期语义计算"的实用性关键指标。

## 3. 对 aemeath 的设计借鉴意义（方向层面）

### 3.1 参照底图：aemeath 现有三条记忆通道

| 通道 | 入口 | 实际行为 | 模型调用 | 触发频率 |
|---|---|---|---|---|
| ① 启动注入 | `MemoryService::retrieve_for_inject` | eligibility 硬过滤 → `order_for_injection`（Synthesized 组优先、组内 injection_score 降序、ID 升序）→ truncate | 0 | Session 首次 + compact 后刷新 |
| ② 每消息召回 | `recall::recall_relevant`（`reminder_sources.rs` 消费） | 词法 20 → **Choice** 重排 top-10 → 取 6 → **top1 概率 ≥ 0.5** 才注入 → 2,500 token 预算逐条截断 | 1 次（恰好 1 候选走 Noul） | 每个 turn 边界 |
| ③ 显式检索 | `search`（`MemorySearch` 工具 / `/memory search`） | relevance 主排序 + 独立 tie-break，`confirm_hits` 刷新确认字段 | 视配置 | 用户/模型主动 |

两个已核实的实现事实（作为对照用的底图，不含改造含义）：

1. `ScoringPort::answer(state, questions[])` 是**批量**接口：一条共享 state 可带多条 question；
2. 通道②已有 Noul 绝对判定原语（`RECALL_SINGLE_NOUL_INSTRUCTIONS`），目前只在"恰好 1 个候选"时触发。

### 3.2 借鉴一：语义成本的位置是一道设计选择题，不是常量

SAG2 真正的动作不是"去掉 embedding"，而是**把语义计算从索引期搬到查询期**，于是准备成本趋近于零、查询成本线性上升。这提示我们：评估任何"预计算 vs 在线计算"的方案时，要问的不只是"便宜不便宜"，而是**成本落在哪个频率上**。aemeath 的通道②每个 turn 都跑、通道③按需跑、通道①每会话一次——三条通道的频率差了两个数量级，任何语义计算方案都应当**按通道频率分别定价**，而不是给一个全局结论。

### 3.3 借鉴二：判定语义决定门控能力的上限

同一个打分模型，问句不同，能力上限不同：

| 判定形态 | 输出 | 能否当绝对门控 |
|---|---|---|
| 相关性判定（relevant / worth recalling） | 概率或分 | 弱：依赖问句措辞与候选质量 |
| **必要性判定**（是否为完整答案所必需，带正负判据） | yes 概率 | 强：有可列举的正例与反例 |
| 候选集内 Choice 排序 | 归一化相对值 | **不能**：换一批候选即漂移 |

SAG2 的贡献之一是把"语义"从形容词式的相关性，改写成**有判据的任务**：中间识别事实算、仅主题相关不算、上下文事实不得归属候选、禁外部知识。这类改写不依赖任何具体模型，属于设计原则层面可以直接借鉴的部分——它解释了我们已知的"相对分不能当绝对门控"为什么会出问题，以及正确的替代方向长什么样（不是调阈值，而是换判定语义）。

### 3.4 借鉴三：单轮检索的能力上限是"词面可达"，反馈才能跨过桥接

SAG2 的消融给出了一个清晰的因果判断：在判定量相同的前提下，**交替式扩展比一次性大候选池高 16.80 点**。反过来看，任何"一次检索 + 一次重排"的架构，其召回上限由首轮候选池决定，重排只能在此池内重排。这是能力边界问题，不是参数问题。

对 aemeath 的含义（方向层面）：通道②③当前的召回上限都锁定在**单轮词法命中**上——问题与记忆无词面重合时直接零命中。SAG2 说明"用已命中内容反向生成检索线索"是跨过该上限的一种可行路径，也同时暴露了它的代价（多轮判定）。是否值得，取决于该通道的频率与延迟预算，而非算法本身优劣。

### 3.5 借鉴四：判定预算是设计的一等对象

SAG2 把"一次查询最多判定多少次"写成了显式常量（340/题），并给出四类提前停止条件与 H=1 这个更省的操作点。这带来的不是性能，而是**可定价、可降档、可回归**：成本是设计参数，不是运行时意外。

对 aemeath 的含义：任何引入"逐条判定 / 多轮判定"的通道，若没有显式的判定上限与提前停止，成本就会随候选数、轮数、上下文长度三者相乘漂移，且不可预测。

### 3.6 借鉴五：共享证据状态，让"还需要补什么"可判定

SAG2 的判定不是对每条候选独立问"你相关吗"，而是在共享证据状态 `E_r` 下问"你是否补上了链条缺的那一环"，末轮还要求对照已有事实重判。这让判定天然带有**互补性**语义，而不只是相关性。

对 aemeath 的含义：当多条记忆同时入选时，"它们合起来是否覆盖了所需信息"是一个比"每条是否相关"更强的问题；而当前的逐条判定结构表达不了这个问题。

### 3.7 借鉴六：输出稳定性是设计责任，不是后处理

三级确定性 tie-break（分数 → 检索名次 → 稳定 id）加上"保集合、保首条"的多样性重排，使 SAG2 的结果可复现、可对账，且不额外花一次模型调用。这属于低成本、可独立评估的设计习惯：**排序在分数打平时必须由确定性规则收口**，否则注入内容会随运行漂移。

### 3.8 借鉴七：对"免 X"叙事保持审慎

"embedding-free"是措辞置换的成功案例：离线成本被搬到在线，总量未必下降（每题约 103 K 输入 token），而延迟这一关键指标没有报告。这提醒我们评估同类方案时问三个问题：**成本搬到了哪里？落在什么频率上？被搬走的那项指标有没有被测量？**

### 3.9 不适用的方向（边界）

| 方向 | 不适用的理由 |
|---|---|
| 托管判定模型作为硬依赖 | aemeath 走本地 scoring daemon + provider 自选档位，且记忆内容属私有数据 |
| 每题十万级输入 token 的上下文重复传输 | 通道②按 turn 触发，成本与轮数相乘 |
| H=2 完整多轮 | turn 级延迟敏感，能力收益需先在其他通道验证 |
| 索引期优化（2.36 s / 25 MiB） | 记忆库是本地 dataset，量与形态都不同，准备成本不是瓶颈 |
| 用检索指标代替端到端效果 | 论文只测证据召回；记忆注入的最终判据是"回答是否变好"，不是"召回了多少" |

## 4. 结论：可迁移的是三条原则

1. **判定语义优先于打分技巧**：能否当门控，取决于问句问的是"相关性"还是"必要性"，而不取决于阈值调得多细；
2. **能力上限由结构决定**：单轮检索的上限是词面可达，跨桥接需要反馈；但反馈必须伴随显式判定预算，否则成本不可控；
3. **给成本定位**：任何语义计算方案先回答"落在哪个频率上、搬到哪一层"，再谈收益。

这三条都不指向具体改动；是否采用、用在哪个通道，需要在明确的频率与延迟预算下单独评估。
